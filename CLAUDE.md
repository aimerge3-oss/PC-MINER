# CLAUDE.md — DROPZONE: AUTO

Telegram Mini App: коллекционирование машин (кейсы), тюнинг деталями, дрэг-гонки с ботами, награды, уровни.
Игровой дизайн и все цифры баланса — в [GDD.md](GDD.md). Состояние работы и следующие шаги — в [PROGRESS.md](PROGRESS.md).

## Как работать с владельцем проекта
- Общение на **русском**. Владелец не программист — объяснять простыми словами.
- **Перед каждой новой фичей задавать уточняющие вопросы** (AskUserQuestion, с рекомендованным вариантом первым). Владелец сам просил «допрашивать по каждому пункту».
- После каждого законченного изменения: проверить в превью → `git commit` → `git push` (GitHub Pages обновляет игру в Telegram за 1–2 мин).
- При каждом выпуске **увеличивать `?v=N`** у всех `css`/`js` в `index.html` (иначе Telegram показывает старую версию из кэша). Сейчас `v=151`.
- Токен бота **никогда не просить в чат** — владелец вводит его сам (`npx wrangler secret put BOT_TOKEN`).
- Тестируя в превью, **сохранять прогресс владельца** в `localStorage` (ключ `dz_backup`), а не в переменную страницы — перезагрузка её стирает. После теста восстанавливать: `state = Rules.migrate(JSON.parse(localStorage.getItem('dz_backup'))); saveLocal()`.

Действия `DUEL_ACTIONS` идут через `runDuelAction` (index.js): вызов кладёт другу `S.duelIn` (`mutatePlayer`), принятие переводит гонку вызвавшего в `go`, отказ/отмена — ставка назад (`Rules.duelRefundFrom`), заезд пишется в `duels`, сопернику — только после его заезда (`ctx.duelOppRun`, `duelSync`). Сообщения бота: вызов, «принял», итог тому, кто ждал. Клиент в режиме сервера опрашивает `/state` раз в 5 с, пока идёт гонка или открыт экран друзей.

Действия `MARKET_ACTIONS` → `runMarketAction`: `marketList` (+строка в `market`), `marketCancel` (лот → cancel, со ставками нельзя), `marketBuy` (пробная покупка → «забрать» лот open→sold одним UPDATE → `marketBuyLocal` с `ctx.mkLot` → продавцу `R.lotSold` через `mutatePlayer`), `marketBid` (`marketBidHold` замораживает в `S.mkBids`, прошлому лидеру `R.mkBidRelease`, выкуп → сразу итог). Итог аукциона `mkFinalize` (победителю вещь, продавцу деньги; без ставок — expired, вещь «Забрать»), номера переходят в реестре `plates`. Уведомления: островок (`notices` kind `mk` с `icon/title/sub`) + бот (купили, перебили, выиграл, продан). Ботов на площадке после релиза нет — только игроки.
- **Контейнеры на сервере (готово, включится с релизом):** таблица `containers` (миграция 010), один за раз. Запуск — админ-бот → «Контейнеры» (вся команда; машина из `EXCL_CARS`+`SECRET_CARS`, старт, срок, галочка рассылки всем) → `/admin/cont-create|cont-end|cont-cancel`, список `/admin/conts`. Идущий контейнер — в настройке `cont_open`, `/state` отдаёт его как `cont` (островок «Идут торги» один раз — `dz_cont_seen`, плашка на экране кейсов). `GET /containers` (что внутри — только после конца). Ставка — действие `contBid` (с `AUCTION.minLevel` = 5 ур., `contBidHold` → `S.contBids`, прошлому лидеру `R.contBidRelease`). Конец — `contFinalize` (при `/state`, `/containers`, раз в час): победителю `S.contWon` → открывает `contOpen` (машина `cont: true`, у эксклюзива `paid` = цена). Бот пишет (перебили, выиграл) только тем, кого нет в игре.
- **Временные кейсы на сервере (готово, включится с релизом):** таблица `ecases` (миграция 011). Админ-бот → «Временные кейсы» (вся команда): кейс владельца — сразу в игре, кейс админа команды — `pending`, владельцу приходит сообщение в админ-бот с кнопками «Подтвердить / Отклонить» (`callback_query` → `ecaseDecide`, срок — с подтверждения). До `EC_MAX` = 3 одновременно, «Закончить» досрочно. Оплата `pay`: `rub` / `stars` / `both` (`Rules.casePay`). Список идущих + неделю закончившихся — настройка `ecases` → `globalThis.EVENT_CASES` (сервер — `loadEcases` в начале каждого запроса; игра — из `/state`). Звёзды со счёта — `openCase {stars, useStars}`, оплата Telegram — товар `ev:<id>` в `shopBuy` → подарок `S.gifts` (машины кейса лежат в подарке — не пропадёт после конца). Везде, где платят звёздами и на счету хватает, — шторка «Списать со счёта / Оплатить в Telegram» (`starChoice` в store.js).

### Состояние и действия
- `state` — прогресс игрока (формат — `Rules.newState()`): деньги, машины `{uid,id,got,parts,paint?,fuel?,fuelTs?}`, склад `inv` (`'slot:tier' → кол-во`), места, коллекция `discovered`, доход `pending/pendingTs`, `stats`, бонус дня, кейс наград, `claimed`, музей, соперники `raceOpps`, незаконченная гонка `race`, `level/xp/quest/dq`.
- `prefs` — настройки интерфейса только на устройстве (`localStorage` `dropzone_prefs_v1`): выбранные кейсы, деталь, быстрое открытие, количество ×N, автопродажа, машина для гонок.
- **Любое изменение прогресса — только через `await api(name, params)`**. Он возвращает `result` или `null` (ошибку уже показал). Никогда не менять `state` напрямую в UI-коде.
  - Режим `MODE = 'local'` (в обычном браузере вне Telegram): `Rules.run` выполняется в браузере, прогресс в `localStorage` `dropzone_auto_v1`.
  - Режим `'server'`: когда задан `API_URL` и игра открыта в Telegram, или в браузере с `?api=http://localhost:8787` (тогда заголовок `X-Dev-User`). Запросы `GET /state`, `POST /action`; ответ `{state, result, now}` или `{error, state, now}`; `clockOffset` выравнивает часы.
- `now()` — время с поправкой на часы сервера; все таймеры UI считать от него.
- Результат действия может содержать `levelUps` → складываются в `levelUpQueue`, поздравление показывается, когда нет анимации и открытой шторки.
- Новое действие = функция в `Rules.actions` (тогда оно автоматически работает и локально, и на сервере) + вызов `api()` в UI.

### UI-конвенции
- Разметка — строками через шаблонные литералы; нажатия — делегирование `document.addEventListener('click')` по `data-act`. Каждый модуль вешает свой обработчик.
- `data-confirm="текст"` на кнопке = подтверждение повторным нажатием (кнопка краснеет, вибрация). Обработчик в `game.js` на первом нажатии вызывает `stopImmediatePropagation()` — поэтому обработчики других модулей срабатывают только со второго нажатия. Для всех продаж/покупок/опасных действий использовать это, а не `confirm()`.
- `spinning = true` во время анимаций (кейс, гонка): `render()` ничего не перерисовывает, вкладки заблокированы (`body.spinning`). `busy` — идёт запрос, повторные нажатия игнорируются.
- Шторки: `openSheet(html)`, `closeSheet()` (перерисовывает экран), `sheetNav(title, back?)`.
- Эмодзи — только через `emo(ch, size)`: на iOS/macOS родные, иначе картинки Apple с jsDelivr (`emoji-datasource-apple@15.1.2`, 64px).
- Картинки машин: `carPic(def, locked, paint)`, для машины игрока — `carPicOf(car)` (учитывает покраску). Детали: `partPic(slot, locked)`.
- Деньги — `money(n)` («1,2 млн ₽»).

## Сервер (выложен: https://dropzone-api.dropzone-api.workers.dev)

## Релизное обновление (тестовая версия)
- Тестовая версия открывается только по ссылке с `?test` (https://f1rst11.github.io/dropzone-auto/?test — запоминается в `localStorage` `dz_test`) или на localhost. Обычный браузер без ключа и Telegram без подписи `initData` видят заглушку «Открой игру в Telegram» (`showOpenInBot`, `tgShell`).
- `NEXT_LOCAL_ONLY = true` в `data.js`: всё новое релизного обновления (магазин, торговая площадка, контейнеры…) видно только в браузере (локальный режим), в Telegram — нет. В UI проверять `nextOn()` (store.js). На релизе — поставить `false`.

- Новые машины `NEXT_CARS` (`next: true`, 19 шт.) и кейс «Новинки» (`onlyNext`, до `NEW_CASE_UNTIL`) видны только когда `Rules.nextActive()` (тест: game.js ставит `NEXT_LOCAL_ON`). Список машин коллекции — только `Rules.baseCars()`, шансы кейса — `Rules.caseDrops(cs)` (`dropsNext` — пересчитаны на ~97% с новыми машинами).
- «Ждут места» (`S.waiting`): машина из наград/контейнера/площадки при полном гараже не продаётся, а ждёт в окне 🎁 (забрать `waitTake` / продать `waitSell`). Включено только в тесте (`nextRules(ctx)` в rules.js), в Telegram пока по-старому — продаётся.

- Сезоны (тест): `SEASON` в data.js (2 недели от `epoch`), `Rules.rollSeason` в `R.run` сбрасывает прогресс через `seasonReset`, сохраняя «вечное»: `hall` (секретки → Витрина славы), `stars` (игровые звёзды, тратятся в магазине `useStars`), `badges`, `vipUntil`, `starSlots`, `starterPack`. Призы — `applySeasonPrize` (тест: `seasonEndLocal` из рейтинга). Рейтинг: «Сезон | Неделя».
- Места в гараже (тест): первое — 500 тыс (`GARAGE.firstPriceNext`), дальше ×2; в Telegram пока 100 тыс.
- Пакеты ₽ за звёзды (тест): `moneyNext` в `SHOP.packs` (`Rules.packMoney`): 50⭐→2 млн, 150→7,5, 500→30, 1000→80, 2500→300 млн; в Telegram до релиза — старые (50⭐→4 млн).
- Номера (тест): лимит только на номера в запасе (не на машине) — `PLATE_STORE.base` 5 + `S.plateSlots` (магазин 15⭐ за +1, до 20, сохраняются в сезонах) + VIP; `Rules.plateRoom`. В Telegram пока старый лимит (машины + 5).
- Доход (тест): % в час по классу `INCOME_BY` (D3 C2,5 B2 A1,5 S1), 3+ машины одной страны в гараже — +10% (`INCOME_SET`, `Rules.setCountries`), VIP копит 8 ч (`VIP.offlineH`). Гонки (тест): бак машины по классу `RACE.carFuelBy`, фальстарт — дисквалификация.
- Тюнинг (тест): слияние `MERGE_NEXT` (100/70/50/30%, при неудаче 1 деталь остаётся, +10% за каждую неудачу уровня — `S.mergePity`, `Rules.mergeChance`); полный сет 8 деталей одного уровня — `FULL_SET` +5% мощности, +1% к доходу (`Rules.fullSet`).
- Задания и бонус дня (тест): бонус дня 14 дней `DAILY_NEXT` (`Rules.dailyList`, пропуск не сбрасывает); новые задания дня (`next: true` в `DAILY_QUESTS`), бонус за все 3 (`DAILY_ALL_BONUS`, `questClaim kind=dailyAll`), недельные `WEEKLY_QUESTS` (3 в неделю, `S.wq`, `kind=weekly`).
- Сезонный пропуск (тест): `PASS` (30 уровней = уровень игрока в сезоне, премиум 250 ⭐ на сезон — `S.passPrem` = id сезона, товар `pass` в `shopBuy`), премиум-награды `passPrem(L)` (на 30 — случайная секретка), бесплатная дорожка = обычные подарки за уровень. Экран `showPass` (profile.js), кнопка в профиле и в магазине. Награды уровня не выдаются сами: `S.passPending` → островок в цветах пропуска (notify.js, класс `pass`) → `passClaim`.
- Эксклюзивные машины (тест): `EXCL_CARS` (data.js), редкость `E` салатовая, только из контейнеров (админка контейнеров), в гонках/тюнинге = S, `secret: true` (не продаются, кроме площадки; в конце сезона — Витрина славы). Стоимость = `car.paid` (цена выигрыша, `Rules.carBase`). Фото — промпты в PROMPTS.md.
- Электромобили (тест): `ev: true` у машины → вместо engine/turbo/gearbox/exhaust (`ICE_ONLY`) 3 свои слота `EV_SLOTS` (motor, battery, reducer — их сила = сумме четырёх заменяемых). `Rules.carSlots(car)`, `Rules.allSlots()`, `slotFits`; в случайном кейсе деталей EV-детали вдвое реже. Фото деталей: img/parts/motor|battery|reducer.webp (пока эмодзи).
- Цены номеров (тест): `PLATE_REAL` — база по региону (Москва 77/97/99/777 — 150 тыс, остальная Москва 90, область 60, Петербург 30, города-миллионники `regionBig` 25, остальные 12 тыс), одинаковые буквы + сильные цифры ×3 (`combo`), «народные» серии везде (`specialAll`: ВОР, ЕКХ); пересверено 17.10 с объявлениями 2026 — в среднем ×0,95 от рынка. С релизом ещё 18 кодов (`PLATE_REGIONS_NEXT`: 80–85, 92, 103, 155, 156, 180–185, 193, 198, 250, 550, 977; `Rules.plateRegions()`). Генерации `priceNext` 32 тыс / 225 тыс / 1,55 млн — окупаемость 92–95%. Было: (Москва 150 тыс … регионы 8 тыс) × множители цифр и букв, с «гашением» при сочетании; сверено с объявлениями 2025–2026. Спецсерии — по регионам (`PLATE_REAL.special`, `Rules.plateSpecial`): АМР 74 — не блатная. Генерация дороже в той же пропорции (`priceNext`, `Rules.plateCasePrice`), окупаемость ~91–95%.
- Поддержка: кнопка внизу Меню → профиль `SUPPORT.url` в Telegram. `SUPPORT.live = false` — только в тесте; чтобы включить у всех — `true` (и выложить сервер).

## Оплата звёздами (живая)
- В Telegram уже продаётся то, что в `SHOP_LIVE` (data.js, сейчас `m50` — 4 млн за 50 ⭐); остальной магазин — с релизом. Игра: `payStars` (store.js) → `POST /invoice` (сервер, `createInvoiceLink`, XTR) → `tg.openInvoice`. Бот: `pre_checkout_query` (проверка `payHandlers.check`) и `successful_payment` → `shopBuy` с `ctx.paid`, один раз по `payments.charge_id` (таблица `payments`, `done=0` — не начислено). Островок «Покупка: …» и сообщение от бота. `/paysupport` → @dropezone_help. Вебхук бота перенастраивается сам при первой оплате (`settings.pay_hook`). **Весь магазин на сервере готов** (стартовый набор, VIP, пакеты, удобства, пропуск): включится сам, когда `NEXT_LOCAL_ONLY = false`. Перед оплатой сервер делает пробную покупку на копии прогресса (`shopDryRun` в `/invoice` и `pre_checkout_query`) — если товар не выдастся (набор уже куплен, гараж полный, пропуск уже есть), звёзды не списываются. Звёзды со счёта (призы сезона) — без окна оплаты (`useStars`).

## История игрока
- `Rules.run` после каждого действия пишет в `S.hist` (последние 100, переживает сезон), если изменились деньги, машины, детали или номера: `{ t, a, c?, m?, ad?, rm?, p?, n? }`. Админ-бот → карточка игрока → «История».

## Команда админов
- Владелец — `ADMIN_IDS` (data.js). Админы команды — `settings.team`, назначает/снимает только владелец (админ-бот → карточка игрока → «Права», раздел «Команда»). Админ команды не может: назначать админов, `reset`/`load`, ставить баланс, давать >100 млн за раз (`ADMIN_MONEY_CAP`); в игре `ctx.admin` — только владелец. Все POST в /admin/* пишутся в `admin_log` (журнал в «Команде», видит владелец).

## Баланс — важные правила
- Кейсы должны окупаться при продаже содержимого **не выше ~100%** (иначе бесконечные деньги «открыл-продал»). Проверять расчётом ожидаемой стоимости при изменении цен/шансов.
- Слияние деталей в среднем «в ноль».
- Последнюю машину в гараже нельзя продать, выставить на площадку или убрать на витрину (`keepLast` в rules.js) — иначе игрок без денег застревает.
- Секретные машины (класс X) в тюнинге и гонках = S (`Rules.carClass`), не продаются, не выпадают из кейсов, в коллекцию (53) не входят.
- Ежедневные таймеры (бонус, задания) — по московскому времени (`Rules.dayKey`).
